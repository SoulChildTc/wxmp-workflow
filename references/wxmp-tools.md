## 爆款标题生成器

基于文章内容生成多个标题选项，帮用户找到最有吸引力的那个。

### 何时使用

- 用户写完文章后不知道怎么取标题
- 用户对现有标题不满意
- 用户说"帮我想几个标题"或"标题太普通了"

### 怎么做

1. 通读文章全文，理解核心观点和目标读者
2. 用以下 6 种策略各生成 2 个标题，共 12 个：
   - **口语法**：像跟朋友聊天一样自然（"说实话，XX 真没那么难"、"我试了 XX，结果出乎意料"）
   - **好奇法**：制造信息缺口（"这个方法让我月入 X"、"90% 的人不知道"）
   - **痛点法**：直击读者焦虑（"你还在 X？"、"为什么你总是 Y"）
   - **数字法**：用具体数字制造确定感（"5 个方法"、"3 分钟学会"）
   - **对比法**：制造反差（"从 X 到 Y，我只做了一件事"）
   - **权威法**：借助背书（"XX 亲测有效"、"行业大佬都在用"）
3. 每个标题必须与文章核心内容直接相关，不能为了爆款而偏离原文
4. 避免 AI 味标题：不用"赋能""助力""深度解析""一文读懂"等套路词
5. 每个标题附带一句话分析：为什么这样写、适合什么读者
6. 按推荐度排序，最推荐的放前面

**被否定后：** 如果用户否定一轮标题，先问"你想要什么感觉的标题？"（比如更口语、更正式、更夸张、更低调），再针对性生成

### 输出格式

```
🏷️ 爆款标题候选（共 12 个）

⭐ 推荐
1. 《xxx》— 口语法，像朋友聊天一样自然
2. 《xxx》— 好奇法，制造信息缺口吸引点击

📌 备选
3. 《xxx》— 痛点法，直击目标读者的核心焦虑
4. 《xxx》— 数字法，用具体数字降低阅读门槛
...

💡 分析：这篇文章的核心价值是 xxx，建议标题突出 xxx，避免 xxx。
```

## 摘要生成器

生成 120 字以内的公众号摘要，用于文章列表展示。

### 何时使用

- 用户不知道怎么写摘要
- 用户说"帮我写个摘要"或"摘要太长了"
- 在创建草稿前自动生成

### 怎么做

1. 通读文章，提炼核心观点
2. 摘要要满足：
   - 120 字以内（公众号限制）
   - 独立可读（不依赖标题）
   - 制造好奇心或承诺价值
   - 避免重复标题已表达的信息
3. 生成 3 个版本让用户选择：
   - **悬念型**：制造信息缺口，吸引点击
   - **价值型**：直接说明文章能给读者什么
   - **故事型**：用一个小故事/场景开头

### 输出格式

```
📝 摘要候选（共 3 个）

1. 悬念型：xxx
2. 价值型：xxx
3. 故事型：xxx

💡 建议：如果文章偏干货，选价值型；如果偏观点/故事，选悬念型或故事型。
```

## 文章体检报告

分析文章的可读性和传播力，给出具体优化建议。

### 何时使用

- 用户写完文章想优化
- 用户说"帮我看看这篇文章怎么样"
- 用户说"有没有什么可以改进的"
- 在转 HTML 之前做一次体检

### 怎么做

从以下 5 个维度打分（每项 1-5 分），并给出具体改进建议：

| 维度 | 检查什么 |
|------|---------|
| 开头吸引力 | 前 3 行是否能抓住读者？有没有制造好奇/痛点/悬念？ |
| 段落可读性 | 段落是否够短（≤4行）？是否有留白？是否适合手机阅读？ |
| 结构清晰度 | 小标题是否清晰？逻辑是否连贯？读者能否扫读？ |
| 金句密度 | 是否有值得划线/转发的句子？大约每 500 字一个金句？ |
| 结尾引导力 | 是否有互动引导（点赞/在看/评论/转发）？ |

### 输出格式

```
📊 文章体检报告

总体评分：xx/25

| 维度 | 评分 | 说明 |
|------|------|------|
| 开头吸引力 | x/5 | 具体分析... |
| 段落可读性 | x/5 | 具体分析... |
| 结构清晰度 | x/5 | 具体分析... |
| 金句密度 | x/5 | 具体分析... |
| 结尾引导力 | x/5 | 具体分析... |

🔧 优化建议：
1. 具体建议（对应哪个维度）
2. 具体建议
3. 具体建议
```

## 去 AI 味检查

AI 生成的文章有明显的"AI 味"——太完美、太中立、太工整、太空泛。去 AI 味是每篇文章打磨的必经步骤，目标是让文章读起来像一个有态度的人在聊天，而不是 AI 在交作业。

> 💡 如果已安装 [Humanizer](https://github.com/blader/humanizer) 和 [StopSlop](https://github.com/hardikpandya/stop-slop)，优先使用它们（Humanizer 去 AI 痕迹 → StopSlop 打磨质量）。以下为内置的兜底规则。

### 何时使用

- 文章写完后、体检报告之前
- 用户说"这文章一看就是 AI 写的"
- 用户说"帮我改得像人写的"
- 每篇文章必经步骤

### 核心策略

去 AI 味有两个入口，**生成时约束比事后修复更有效**：

1. **写稿阶段（推荐）：** 在写稿 prompt 中加入结构性约束，让 AI 从源头避免 AI 味（见下方「生成时约束」）
2. **打磨阶段（兜底）：** 写完后用 4 轮扫描 + 量化评分 + 迭代闭环修复

### 生成时约束（写稿阶段使用）

在写稿 prompt 末尾加入以下约束，比事后修复效果好 2-3 倍：

```
写稿约束：
1. 每一段必须有长短句交替——至少一个短句（<10字）和一个长句（>25字）
2. 禁止使用「不是...而是...」句式
3. 禁止使用「从...到...」的跳跃式范围
4. 禁止使用「值得注意的是/不容忽视的是/重要的是要记住」
5. 全文至少出现 3 处「不确定」的表达（"我也没搞明白""可能""我不太确定"）
6. 允许废句存在——不是每句话都要推进论点
7. 每段不超过 2 句话（倒逼不规则节奏）
```

### 打磨阶段：4 轮扫描 + 量化评分 + 迭代闭环

#### 4 轮扫描

##### 第 1 轮：查 AI 特征词 + 句型指纹

**过渡词滥用（删除或换掉）：**
| AI 词 | 换成 |
|-------|------|
| 值得注意的是 | [删掉] |
| 需要指出的是 | [删掉] |
| 不仅如此 | 而且、还不止这些 |
| 与此同时 | 这时候、同一时间 |
| 换言之 / 换句话说 | [删掉，直接说] |
| 值得深入探讨 | [删掉] |

**空洞高级词（换成具体表达）：**
| AI 词 | 换成 |
|-------|------|
| 赋能 | 帮你、让...能 |
| 深耕 | 专注、一直做、埋头研究 |
| 打造 | 做、搞、弄 |
| 构建 | 搭、建 |
| 驱动 | 推动、带着走 |
| 助力 | 帮、让 |
| 旨在 | 就是想 |
| 致力于 | 一直在 |
| 颗粒度 | 细节、具体程度 |
| 底层逻辑 | 本质、根本原因 |
| 闭环 | 完整流程、从头到尾 |
| 场景化 | 结合实际场景 |

**套话开头/结尾（删掉或重写）：**
| AI 词 | 怎么改 |
|-------|--------|
| 在当今社会 | [删掉，直接切入] |
| 随着...的发展 | [删掉，用故事/数据开头] |
| 在这个...的时代 | [删掉] |
| 不可否认 | [删掉或换成"说真的"] |
| 毋庸置疑 | [删掉] |
| 众所周知 | [删掉] |
| 总而言之 / 综上所述 | [删掉，直接说结论] |
| 总之 | 所以说、反正 |

**模糊万能表达（换成具体）：**
| AI 词 | 换成 |
|-------|------|
| 在一定程度上 | [删掉或给具体程度] |
| 从某种角度来看 | [删掉或给具体角度] |
| 具有重要意义 | [具体说有什么意义] |
| 深远影响 | [具体说影响是什么] |
| 不容忽视 | [删掉] |
| 方方面面 | [具体列举] |

**新增：句型指纹扫描（AI 最暴露的 6 种句式模式）：**

| 句型指纹 | 特征 | 怎么改 |
|----------|------|--------|
| 否定平行结构 | "不是...而是..." / "不只是...更是..." | 直接陈述，不玩对比游戏 |
| 虚假范围 | "从 X 到 Y" 且 X 和 Y 跨度极大无逻辑 | 砍掉范围，只说其中一个 |
| 三段式排比 | "融合了 A、B 与 C" 连续三个并列 | 只留最有力的一个 |
| 模糊归因 | "批评者认为""观察家指出""有研究表明" | 换具体人名或删掉 |
| 僵化结尾 | "尽管面临挑战，但..." / "总之"/"总的来说" | 直接结尾，不总结 |
| 说教式开头 | "重要的是要记住""不容忽视的是" | 删掉，直接说事 |

##### 第 2 轮：查结构问题 + 句子节奏

| 问题 | 怎么改 |
|------|--------|
| "首先...其次...最后" 刻板结构 | 换成自然过渡，或只保留重点 |
| 连续 3+ 个排比句 | 只留最有力的一个，其他换表达 |
| 段落过渡太顺滑 | 允许逻辑跳跃，新段直接起新话题 |
| 总-分-总模板 | 换结构：故事先行、结论先行、夹叙夹议 |
| "一方面...另一方面" 两面讨好 | 亮明立场，敢下判断 |
| 句子长度均匀（每句都在 15-25 字之间） | 打乱：加一句 <10 字的短句，加一句 >25 字的长句 |
| 段落长度均匀（所有段落差不多长） | 故意让某一段特别短或特别长 |
| 所有句子都是主干结构（主谓宾） | 加倒装、插入语、前置状语 |

##### 第 3 轮：查风格问题

| 问题 | 怎么改 |
|------|--------|
| 全文语气平淡，没有情绪起伏 | 加情绪高点：惊讶、吐槽、兴奋 |
| 大量用"我们"，称呼疏远 | 换成"你""我"，像跟朋友聊天 |
| 举例空泛："很多人""有研究表明" | 用具体的人、具体的数、具体的场景 |
| 过度客套："希望对你有帮助" | 删掉或换成有态度的结尾 |
| 没有个人观点，纯客观陈述 | 加"我觉得""说实话""我的经验是" |
| 成语用得太工整 | 少用四字成语，换成口语表达 |

##### 第 4 轮：加人味（必做）

检查文章是否有人的痕迹，没有就补：

| 人味元素 | 示例 |
|----------|------|
| 个人经历 | "我去年试过这个方法，结果翻车了..." |
| 具体细节 | "昨天微信更新到 8.0.44 之后..." |
| 明确立场 | "这方法就是垃圾，别浪费时间了" |
| 幽默/自嘲 | "我又踩坑了，这次是第 23 次" |
| 不完美的观点 | "我也没想明白，但先这么干着" |
| 反问/自问 | "这事儿靠谱吗？" |
| 断句/碎句 | "说白了。""问题是——" |
| 口语感 | "说实话""其实吧""你想想""怎么说呢" |

#### 量化评分

4 轮扫描完成后，跑一次 AI 味评分，量化改进效果：

```
AI 味评分（1-10，10=纯 AI，1=完全不像 AI）

评分维度及权重：
1. 特征词密度（30%）：禁用词命中次数/千字
2. 句子长度方差（25%）：段落内句子长度标准差（<5 需修复）
3. 段落长度方差（15%）：全文段落长度标准差
4. 具体性密度（20%）：具体名词/数字/专有名词占比
5. 口语化表达（10%）：口语词、断句、情绪标点出现频率

评分标准：
- 1-3 分：自然，通过
- 4-6 分：轻微 AI 味，建议修复
- 7-10 分：AI 味重，必须返工
```

#### 迭代闭环

评分 > 4 分时，执行迭代修复：

```
1. 找出评分最低的维度
2. 针对该维度修复（对应 4 轮扫描中的相关轮次）
3. 重新评分
4. 如果分数下降（Δ < -1），保留修复，继续
5. 如果分数不变或上升，回退修复，换方向
6. 循环直到评分 ≤ 4 分，或连续 2 轮 Δ < 0.5 分（触顶，收手）
```

### 输出格式

```
🔍 去 AI 味检查 — AI 味评分：7/10 ⚠️ 需返工

━━━ 第 1 轮：特征词 + 句型指纹 ━━━
❌ "赋能" → 改成"帮你"
❌ "值得注意的是" → 删掉
❌ [否定平行结构] "不是...而是..." 出现 2 次 → 直接陈述
❌ [虚假范围] "从代码到哲学" → 砍掉，只说代码
...共 x 处

━━━ 第 2 轮：结构 + 节奏 ━━━
❌ 句子长度标准差 4.2（<5）→ 加一句短句和一句长句
❌ "首先...其次...最后" → 删掉连接词，直接讲重点
...共 x 处

━━━ 第 3 轮：风格 ━━━
❌ 第 2 段举例空泛 → 补具体数据/案例
❌ 全文没有明确立场 → 在关键观点上表态
...共 x 处

━━━ 第 4 轮：人味 ━━━
⚠️ 缺少个人经历 → 建议在第 2 段加一个亲历故事
⚠️ 缺少口语表达 → 加入"说实话""你想想"等
...共 x 处

💡 修复建议：特征词密度得分最高，优先修复 L1；修复后重跑评分目标 ≤ 4 分
```

## 话题标签推荐

根据文章内容推荐适合的公众号话题标签。

### 何时使用

- 用户说"帮我加几个标签"
- 在发布前自动推荐

### 怎么做

1. 提取文章的核心关键词（3-5 个）
2. 结合公众号热门话题，推荐标签
3. 每个标签说明为什么适合这篇文章

### 输出格式

```
🏷️ 话题标签推荐

推荐标签：
1. #关键词 — 理由
2. #关键词 — 理由
3. #关键词 — 理由

💡 标签不宜过多，3-5 个为佳。优先选搜索量大但竞争适中的标签。
```
